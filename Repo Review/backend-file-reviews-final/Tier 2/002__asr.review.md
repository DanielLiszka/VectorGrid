## Consolidated Judgment

The earlier passes were right to keep this file in the smallest bucket and to avoid broad cleanup. `asr.rs` is still a strategy-owner surface spanning config, CPU/GPU signal construction, desired-position generation, and trade/stat emission. That makes parity and compatibility more important than symmetry-driven refactoring.

The fourth pass correctly reranks the remaining work. The strongest live defect is no longer abstract route caution. It is trade-level correctness in [simulate_from_desired](</C:/Rust Projects/ta_desktop_demo/crates/app_core/src/asr.rs:2173>): per-trade `trade_log_ret` can understate real trade pnl, and ordinary signal exits/flips can miss exit-side commission in the recorded `Trade` even while account-level equity remains correct. No wrong `review_fourth_pass.md` is present in this folder.

## Safe-Now Priority

- Fix `trade_log_ret` accumulation so ordinary bar returns contribute to open trades even when stop-loss and take-profit risk management are disabled.
- Include exit-side commission in the closing `Trade` for ordinary signal exits and flips before the trade is pushed.
- Tighten [validate_asr_params](</C:/Rust Projects/ta_desktop_demo/crates/app_core/src/asr.rs:377>) so `z_nbdev` must be finite and strictly positive.
- Expand route diagnostics across the direct CUDA helper family while preserving current fallback behavior; the safe-now change is observability, not stricter routing.
- Add focused tests proving closed-trade pnl changes with ordinary bar returns when stop/take logic is off and that signal exits include exit-side commission in trade-level stats.
