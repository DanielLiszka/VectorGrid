## Consolidated Judgment

The first three passes were right to defer any broad redesign here. `mo.rs` is shared optimizer-core infrastructure, and its heuristic defaults, duplicate handling, and frontier behavior are too policy-sensitive for casual cleanup. The fourth pass is the first one that identifies enough bounded, evidence-backed hardening work to justify action without reopening the larger architecture.

That said, the fourth-pass packet is slightly too broad in where it places the highest-confidence non-finite issue. The main in-repo risk is not `Objectives2::normalize()` in isolation. The stronger live problem is the unsanitized `EvalOutcome -> MoPoint` ingestion path, plus `overall_violation()` collapsing non-finite constraints to zero and constrained-frontier helpers tolerating broken points too permissively. That nuance does not change the bucket. It changes where the safe-now fix should land.

No wrong fourth-pass packet is present in this folder. The packet belongs to the correct file and cites the right live code paths.

## Safe-Now Priority

- Add an explicit Sobol dimensionality preflight before `Sobol::<f64>::new(...)` so oversize spaces return `Err` instead of panicking through a `Result`-returning search API.
- Centralize non-finite hardening at the `EvalOutcome` ingestion boundary so broken objective or constraint values are pessimistic and never become feasible or favorable optimizer state by accident.
- Add focused regression tests for:
  - non-finite constraints in `overall_violation()`
  - feasible-point frontier behavior when second-objective values are non-finite
  - Sobol search with more than 100 dimensions
  - the current Bool-axis `max_axis_values` carveout in exact-grid enumeration
- Either align the Bool exact-grid axis-limit behavior with the public contract, or narrow the rustdoc to state that Bool is a fixed two-value axis.
- Keep any `sample_param()` hardening additive only. A checked sibling helper plus internal migration is safer than breaking the current public signature.

## Deferred Work

- Defer splitting the file by search family or responsibility.
- Defer heuristic retuning for NSGA-II, TPE, or QMC.
- Defer unifying TPE duplicate handling with the richer equality-aware cache path used elsewhere.
- Defer any signature-breaking redesign of the public sampling helpers.
