# Deep Research Response Intake

Save one Markdown file per completed response in this folder.

## Filename convention

Use:

- `DR-01_selective_vectorbt_parity.md`
- `DR-04_validation_stack_and_overfitting_defense.md`
- `DR-09_minimum_useful_options_parity_envelope.md`

Keep the stable question ID at the start of the filename.

## Recommended response header

```md
# DR-XX - Title

Date:
Source:
Question file:
Question ID:
Decision candidate:
```

## Minimum contents

Each saved response should preserve these sections from the answer contract:

1. `Direct answer`
2. `Why this matters for VectorGrid`
3. `What comparable tools already do`
4. `Best fit for VectorGrid`
5. `Recommendation`
6. `Change shape`
7. `Smallest useful implementation slice`
8. `Verification and benchmark plan`
9. `Main risks or counterarguments`
10. `Open questions, if any`

## Practical note

Do not edit the original research answer to make it look more certain than it was.

If you want to add your own interpretation, append a clearly labeled section such as:

- `Operator notes`
- `Questions for repo validation`
- `Reasons this may not fit current scope`
